# Governed DEBO → NATT Request Worker v1

## Role separation

DEBO owns engagement intake, written-authorization references, scope, approvals, dispatch signing, and operator stop requests. NATT owns independent validation, worker claim, technical execution, result integrity, and execution-state history.

NATT does not accept arbitrary conversational text as an execution instruction. It accepts only a signed request envelope generated by the DEBO Unchained request controller.

## Commands

Validate pending requests without executing testing:

```bash
pnpm natt:requests:check
```

Execute validated requests in the approved NATT runtime:

```bash
DEBO_NATT_EXECUTION_ENABLED=true pnpm natt:requests:run
```

Process one request:

```bash
pnpm tsx .natt/requests/worker.ts \
  --execute \
  --request <request-id> \
  --worker-id natt-worker-01 \
  --lease-seconds 120 \
  --json
```

## Mandatory environment

```text
DEBO_NATT_REQUEST_SECRET       shared signing secret supplied by secret manager
DEBO_NATT_EXECUTION_ENABLED    must equal true for execution
<missionPassphraseEnv>         engagement-specific ROE passphrase reference
```

`NATT_PATHFINDER=true` causes an immediate rejection.

## Validation order

1. Atomically move the request from `pending/` to `processing/`.
2. Parse the versioned envelope.
3. Verify HMAC-SHA256 using constant-time comparison.
4. Validate the DEBO request event chain and queued lifecycle.
5. Reject duplicate request IDs and duplicate idempotency keys.
6. Establish a worker-owned execution lease.
7. Validate exact target membership in approved scope.
8. Verify separate client and security approvers.
9. Verify the current time is inside the approved testing window.
10. Verify mandatory hard limits.
11. Verify auth-testing identity references and attempt limits.
12. Verify execution environment and mission passphrase availability.
13. Transition `claimed → validating → running`.
14. Invoke only `runNattFromProfile`.
15. Record terminal state and SHA-256 result digest.

The worker deliberately does not expose `runPentestFromProfile` and does not construct shell commands from the DEBO request.

## Execution state

The worker stores a separate state journal under:

```text
.natt/requests/state/<request-id>.json
```

State contains:

- Lifecycle and optimistic revision.
- Source DEBO request revision.
- Idempotency key.
- Worker ID and lease UUID.
- Lease acquisition, heartbeat, and expiry timestamps.
- Append-only hash-chained events.
- Terminal timestamp and blocked reason.
- Result digest without embedding credentials or raw secrets.

Only the current lease owner may mutate an execution. Lease renewal creates an audited `lease-heartbeat` event and increments the revision.

## Emergency stop

DEBO writes:

```text
.natt/requests/control/<request-id>.stop.json
```

The worker checks the control record before execution, during lease heartbeats, and after the NATT adapter returns. Results produced after a stop request are quarantined and marked `stopped`.

The current adapter executes in-process and cannot be terminated instantly. Production should run each mission in an isolated child process, container job, or queue worker with a cancellable execution handle.

## Stale leases

A stale running execution is never replayed automatically. The Neon migration exposes `debo_security.stale_execution_leases` as a manual-recovery queue. An authorized operator must determine whether the mission is still active, failed, or safe to close before any retry.

## Production database contract

The canonical shared schema is:

```text
contracts/debo-natt-state.schema.json
```

The Neon/PostgreSQL implementation is owned by the DEBO repository:

```text
db/migrations/001_debo_natt_state.sql
db/migrations/002_debo_natt_execution_transitions.sql
```

It provides tenant-scoped engagements, separate approvals, append-only event journals, NATT execution leases, idempotency constraints, transition procedures, row-level security, result quarantine metadata, and manual stale-lease recovery.

## Release blockers

- Remove the unrestricted NATT bypass from the underlying ROE module.
- Replace simplified CIDR matching.
- Isolate mission execution for preemptive cancellation.
- Verify signed Authorization-to-Test documents rather than trusting a hash reference alone.
- Move local queue files to a durable transactional queue for multi-node execution.
- Complete independent legal and security review.
